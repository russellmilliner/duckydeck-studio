DuckyDeck Studio (v0.1.6) is a native Linux (KDE Plasma 6 / Wayland & X11) and Windows 10/11 (x86_64) desktop configurator, DSVM v2 bytecode compiler, Window-Aware Auto-Switcher, and host automation daemon for the duckyPad Pro (0x0483:0xd11d) and duckyPad 2020 (0x0483:0xd11c).

🏛️ 1. System Overview & Core Design Philosophy

⚡ 1. Zero-Runtime-Wrapper Native Stack

Built directly in Rust bridged to Qt 6 via CXX-Qt 0.7, avoiding Electron or Python runtime overhead. On Linux, it uses native KDE Frameworks 6 (Kirigami + KSyntaxHighlighting); on Windows 10/11, it uses a self-contained Kirigami QML Compatibility Layer (src/qml/kirigami/) and Qt Fusion Dark/Light palette sync.

💾 2. Offline-First & Deterministic SD Sync

All profile edits, key scripts, RGB LED overrides, and rule bindings are immediately persisted to a per-device local cache (~/.local/share/duckydeck-studio/profile_cache/<serial>/ on Linux or %LOCALAPPDATA%\duckydeck-studio\profile_cache\<serial>\ on Windows) and compared against the hardware microSD state using SHA-256 content fingerprinting before writing and read-back validating .dsb bytecode.

⚙️ 3. Pure-Rust DSVM v2 Compiler

Compiles duckyScript 3 (keyN.txt / keyN-release.txt) directly into duckyPad virtual machine bytecode (.dsb) with live syntax diagnostics, Shunting-Yard RPN expression evaluation, control flow (IF/ELSE/WHILE), functions, OLED graphics primitives, and PGV (_GV0.._GV31) access.

🔄 4. Bidirectional Hardware-Host Automation

Combines KWin Wayland window focus events (zbus D-Bus listener on Linux) and Win32 foreground window tracking (GetForegroundWindow on Windows) for automatic profile switching (Host → duckyPad) with USB HID PGV polling (_GV31 encoded via encode_pgv31_trigger) and global F13–F24 shortcut triggers for Web API webhooks and Desktop Application Launching (duckyPad → Host).

🔗 4. CXX-Qt Concurrency Model & _GV31 Trigger Encoding

Because Qt GUI objects (QObject) have strict single-thread affinity on the Qt main event loop thread, src/bridge/device_controller.rs separates state into Qt-thread-owned fields and thread-safe shared registries:

  • Qt-Thread Owned State (DeviceControllerRust): Holds profiles: Vec<DuckyProfile> (up to 64 profiles), sd_root_path: Option<PathBuf>, and copied_slot: Option<DuckyKeySlot>.
  • Thread-Safe Shared State (Arc<Mutex<...>> / Atomics): Holds switcher_state, WEB_API_REGISTRY, WEB_API_PGV_REGISTRY, APP_LAUNCH_FKEY_REGISTRY, APP_LAUNCH_PGV_REGISTRY, and SYSTEM_EVENT_LOG.
  • Cross-Thread UI Updates (CxxQtThread): Background worker threads never mutate QProperty values directly; they capture let qt_thread = self.qt_thread(); and queue closures onto the Qt event loop via qt_thread.queue(move |mut qobject| { ... }).

Unified _GV31 Hardware-to-Host Trigger Word

Both Web API (// @DUCKYDECK_WEBAPI) and Desktop Application Launch (// @DUCKYDECK_APPLAUNCH) scripts in pgv trigger mode write a 32-bit magic word into Persistent Global Variable _GV31 (PGV_TRIGGER_INDEX = 31): 

// 32-bit _GV31 Trigger Word Layout:
// Bits 16..31 : 0x5741 ("WA" magic header)
// Bit  15     : is_release (0 = On Press, 1 = On Release)
// Bits 8..14  : profile_num (1..64)
// Bits 0..7   : slot_num (1..58)
pub fn encode_pgv31_trigger(profile_num: u8, slot_num: u8, is_release: bool) -> u32 {
    let rel_bit = if is_release { 0x8000 } else { 0 };
    0x5741_0000 | rel_bit | ((profile_num as u32 & 0x7F) << 8) | (slot_num as u32)
}

When the background USB HID poller reads _GV0.._GV31 via command 0x18 (HID_CMD_DUMP_PGV) and detects a non-zero _GV31 matching decode_pgv31_trigger, it immediately writes _GV31 = 0 via command 0x19 (HID_CMD_WRITE_PGV) to re-arm the trigger and dispatches the matching WEB_API_PGV_REGISTRY or APP_LAUNCH_PGV_REGISTRY action on the Linux or Windows host.

🔌 5. USB HID Protocol, USB Mass Storage & Cross-Platform Volume Sync

5.1 64-Byte USB HID Report Protocol (src/hardware/storage.rs)

The duckyPad Pro (0x0483:0xd11d) and duckyPad 2020 (0x0483:0xd11c) communicate over a 64-byte vendor-defined USB HID interface (HID_REPORT_ID_OUT = 0x05):

Command Byte (tx[2]) Constant Name Description
0x00 HID_CMD_QUERY_INFO Returns firmware version, hardware model, serial number, active profile, and 'D','D','S' custom firmware capability signature.
0x01 HID_CMD_GOTO_PROFILE_BY_NUM Switches the active hardware profile by number (1..=64).
0x04 HID_CMD_SET_LED_SINGLE Sets key RGB LED overrides in real time.
0x14 HID_CMD_SOFTWARE_RESET Reboots the duckyPad firmware (tx[3] = 0 normal HID mode, tx[3] = 1 USB Mass Storage mode).
0x17 HID_CMD_GOTO_PROFILE_BY_NAME Switches the active hardware profile by folder name.
0x18 HID_CMD_DUMP_PGV Reads all 32 32-bit Persistent Global Variables (_GV0.._GV31, 128 bytes) across 3 burst packets (start_idx = 0, 15, 30).
0x19 HID_CMD_WRITE_PGV Writes up to 12 (pgv_index | 0x80, i32_le) entries per packet into _GV0.._GV31.

5.2 USB Mass Storage (MSC) Mounting & Flatpak / Windows Volume Handling (src/hardware/msc.rs)

When reading or writing profiles or staging firmware on a duckyPad Pro, DuckyDeck Studio sends HID command 0x14 (tx[3] = 1) to enumerate the microSD card as a TinyUSB Mass Storage block device. On Linux, it locates /dev/disk/by-label/DP24_* or /dev/disk/by-id/*TinyUSB_Flash_Storage* and mounts the FAT32 partition via udisksctl mount --no-user-interaction -b /dev/sdX1. On Windows 10/11, it scans removable drives D:\..Z:\ for duckyPad profile signatures, flushes dirty buffers via FlushFileBuffers, and safely ejects the drive via PowerShell Shell.Application before rebooting back into HID mode (0x14, tx[3] = 0).

📦 Flatpak Host Storage Bridge (run_storage_cmd)
Inside the Flatpak sandbox (org.kde.Platform//6.11), host utilities like udisksctl and umount are not installed inside the container's /usr/bin. src/hardware/msc.rs automatically detects /.flatpak-info and routes udisksctl, umount, sync, and host /proc/mounts queries through flatpak-spawn --host while accessing the mounted filesystem directly via --filesystem=/run/media:rw and --filesystem=/media:rw.

⚙️ 6. DSVM v2 Bytecode Compiler (src/vm/compiler.rs)

The duckyPad Pro executes compiled DSVM v2 (.dsb) stack-machine bytecode binaries rather than interpreting raw text on-device. src/vm/compiler.rs implements a complete two-pass compiler in pure Rust:

1️⃣ Preprocessor & Directive Preservation

Strips comments while preserving structured visual-builder metadata directives (// @DUCKYDECK_WEBAPI {...} and // @DUCKYDECK_APPLAUNCH {...}), expands DEFINE macros safely (with recursion/expansion caps), and injects $_ALLOW_ABORT / $_DONT_REPEAT header flags.

2️⃣ Block & Control-Flow Parser

Resolves nested IF / ELSE_IF / ELSE / END_IF, WHILE / END_WHILE, LOOP0..LOOP9 state machines, and FUNCTION / RETURN call frames into structured intermediate labels.

3️⃣ Shunting-Yard RPN Expression Engine

Converts infix arithmetic, bitwise, comparison, and boolean expressions into stack-based RPN instructions (OP_PUSH_CONST, OP_PUSH_VAR, OP_ADD, OP_EQ, OP_BITWISE_AND) and maps user variables alongside hardware globals (_GV0.._GV31).

4️⃣ Two-Pass Linker & Bytecode Emitter

Resolves 16-bit jump target offsets and null-terminated UTF-8 string pool addresses across two passes, emitting little-endian .dsb binaries verified for parity against official DSVM v2 semantics.

🪟 7. Cross-Platform Window Auto-Switcher (KWin Wayland & Windows Win32), IPC & Rule Invariants

DuckyDeck Studio implements automatic active-window profile switching and single-instance IPC on both Linux (KDE Plasma 6 Wayland) and Windows 10/11 (Win32):

  • Linux (KWin Wayland + Session D-Bus io.github.duckydeck.Studio at /KWinBridge): Dynamically loads a KWin 6 JavaScript hook (duckydeck-kwin6-hook.js) that invokes ReportActiveWindow(window_class, window_title) and ReportPickedWindow(window_class, window_title) over zbus, plus DispatchIpcCommand for CLI/tray IPC.
  • Windows 10/11 (Win32 Foreground Tracker + Named-Pipe IPC): Polls GetForegroundWindow(), GetWindowTextW, GetWindowThreadProcessId, and QueryFullProcessImageNameW every 150 ms to resolve active process names and window titles, provides an interactive hover-and-click Window Picker via WindowFromPoint + GetAsyncKeyState(VK_LBUTTON), and handles single-instance CLI IPC over QLocalServer (duckydeck-studio-ipc).

Profile Fallback & Auto-Switcher Synchronization Invariants

  • Default Fallback Profile Guarantee: Whenever a new profile group is created or loaded, if no profiles exist, Profile #1 ("Default") is automatically created and marked as the fallback_profile.
  • Non-Deletable Fallback Profile: delete_profile rejects deletion of the currently configured fallback_profile so unmatched windows and reassigned rules always have a valid target.
  • Automatic Rule Remapping on Reorder & Delete: Reordering profiles (remap_rules_on_profile_reorder) atomically updates fallback_profile and every rule's target profile number/name. Deleting a profile (remap_rules_on_profile_delete) shifts higher indices down by 1 and reassigns any rule referencing the deleted profile to the fallback_profile.

First-Run Deck Setup, Legacy Migration & Conflict Resolution

  • Conflicting Process Detection: Detects legacy background processes (duckypad_autoprofile.py, duckypad_autoswitcher, duckypad_configurator) via /proc on Linux or tasklist on Windows, offering one-click graceful shutdown to prevent USB HID bus contention.
  • Profile & Rule Discovery: Discovers profiles from the deck microSD, local cache, and legacy dekuNukem backups (~/.local/share/duckypad_config/profile_backups/ on Linux or %APPDATA%\dekuNukem\duckypad_config\profile_backups\ on Windows). Discovers rules from microSD duckydeck_rules.json, local rules, and legacy auto-switcher files (~/.local/share/duckypad_autoswitcher/ on Linux or %APPDATA%\dekuNukem\duckypad_autoswitcher\ on Windows).
  • Portable SD Rules Bundle: duckydeck_rules.json on the microSD card syncs auto-switcher rules alongside hardware profiles, enabling instant cross-machine rule portability.
  • Onboarding State Tracking: Persists completion in first_run_onboarding_state.json across local and host configs.

🎨 8. Keycap Layout, OLED Desktop Widget & Automated UI Verification

🎹 Option C Header-Footer Split Keycap Layout

Each mechanical keycap cell in src/qml/HardwareCanvas.qml uses a non-overlapping 3-zone vertical structure: a 15px top header strip (key number + pill-shaped RGB LED bar), a centered 2-line OLED preview area, and a 15px bottom footer strip (APP/API host badges + ↻/⏹ execution flags).

🖥️ 4-Way Rotated Desktop OLED Widget

src/qml/OledDesktopWidget.qml and the KDE Plasma 6 Applet (plasmoid/io.github.duckydeck.oled) support per-profile orientation (0°, 90°, 180°, 270°, or Follow Hardware OLED), applying both 4×5 grid coordinate remapping and in-key text rotation.

Automated Scene-Graph UI Test Suite (Linux Native, Flatpak & Windows 11)

src/qml/EventLogDialog.qml and src/main.rs include a comprehensive automated UI verification harness (--ui-test-suite) that walks all 208 window/drawer/modal states across both Dark Mode and Light Mode at 100% and 115% zoom levels on both Linux and Windows 11, auditing:

  • Zero Overflow & Overlap Violations: Audits 160+ keycap instances and all text labels for truncation or sibling bounding-box collisions.
  • WCAG Contrast & High-Contrast Controls: Verifies text/background contrast ratios, HighContrastCheckBox border luminance, and 40+ HighContrastScrollBar instances.
  • 12 Behavioral Invariants: Verifies profile group creation, non-deletable fallback protection, profile reorder/delete rule remapping, Escape-key modal dismissal, zoom persistence, and bundled DuckyDeck Studio custom firmware catalog presence (duckydeck_studio_firmware_available_in_catalog).

🌐 9.7 Embedded HTTP REST API Server (src/api_server.rs)

DuckyDeck Studio embeds a bounded, stoppable/restartable HTTP/1.1 REST API server (src/api_server.rs and src/bridge/rest_routes.rs):

  • Default Security Posture: Disabled by default (rest_api_enabled = false), bound to loopback 127.0.0.1:28491, with constant-time Bearer Token authentication (ddk_<40 hex chars> stored in OS keyring).
  • Resource Bounds: Capped at MAX_CONCURRENT_CONNECTIONS = 8 (returning 503 Service Unavailable when full) and MAX_BODY_BYTES = 2 MB (returning 413 Payload Too Large).
  • Async Worker Jobs (202 Accepted): Long-running hardware operations (/api/v1/sd/sync, /api/v1/sd/mount, /api/v1/sd/unmount, /api/v1/device/reboot) return 202 Accepted with a job ID pollable via GET /api/v1/jobs/{id}.
  • Interactive Documentation: Full OpenAPI 3.0.3 & Swagger 2.0 specs are served at /api/v1/openapi.yaml, /api/v1/openapi.json, and /api/v1/swagger.json (and documented in REST_API.md).

📦 10. Linux Flatpak Sandbox & Windows 10/11 Packaging
